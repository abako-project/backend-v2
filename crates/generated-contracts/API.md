# Shared HTTP contract

All bodies use JSON with camelCase fields. Enum values use PascalCase. IDs and
signatures are 0x-prefixed hex; KVN amounts are decimal strings in integer token
units. Timestamps are Unix seconds and weeks are `{isoYear, week}`. Unknown request
fields are rejected. Provider commands are internal only, never a public generic
signing endpoint. Consumers must validate commands before signing and again after
decoding at the provider. State authorization runs in the provider transaction.

## Internal endpoints

All require `Authorization: Bearer <INTERNAL_SERVICE_TOKEN>` and stay outside the
public reverse proxy. Ports: adapter 8080, custody 8081, provider 8082.

| Service | Endpoint | Request | Response |
|---|---|---|---|
| Custody | POST /internal/wallets | ProvisionWalletRequest | WalletView |
| Custody | GET /internal/system-wallet | — | WalletView, principalId=null |
| Custody | POST /internal/signing-jobs | CreateSigningJobRequest | 202 SigningJobView |
| Custody | GET /internal/signing-jobs/{operationId} | — | SigningJobView |
| Provider | GET /internal/info | — | ProviderInfo |
| Provider | GET /internal/accounts/{account}/nonce | — | AccountNonce |
| Provider | POST /internal/contracts/call | SignedContractCallV1 | OperationReceipt |
| Provider | GET /internal/receipts/{operationId} | — | OperationReceipt or 404 |
| Provider | GET /internal/events?after=0&limit=100 | — | ProviderEvents |
| Provider | GET /internal/snapshot | — | ProviderSnapshot |

The unsigned call fixes a 16-byte signing domain and payload version 2. The command
variant identifies the message; its typed IDs identify contract instances. No
redundant arbitrary message/contract/opaque payload can contradict this command.
SHA-256 covers exact SCALE bytes returned by `signable_bytes()`. A receipt records
finality separately from execution outcome; exact authenticated replay retrieves
the receipt before checking expiry or next nonce for a new execution.

## Public endpoints

Authenticated mutations require the session cookie and `X-CSRF-Token`. Browser
origins must be in the exact allowlist. Business mutations return 202 OperationRef;
poll GET /api/operations/{operationId} for OperationView. A supplied
`Idempotency-Key` is an OperationId, scoped and bound to the authenticated principal
and exact typed action by the adapter. A missing key may be generated by the
adapter, but clients needing retry safety should always supply one.

Administrator-only typed routes map catalog edits, coordinator promotion, score
policy and dev funding to their corresponding request DTOs and closed commands.
The public request never selects a privileged wallet or spoofed origin.

Planning and proposal read models expose a provider-owned `revision`. Acceptance
bodies are `{"expectedRevision":7}`: planning accept and accept-delivery use the
observed planning revision; execution approval uses the observed proposal revision.
The adapter copies this value into the signed command. The provider compares it
inside the execution transaction before transferring funds or reserving capacity;
a mismatch returns `revision_conflict` without business effects. Revisions start
at zero and increment with checked arithmetic on relevant definition/status
changes. A planning delivery or replacement delivery changes the planning revision,
so acceptance cannot pay for a plan different from the one the client reviewed.
Revisions are not generated or automatically refreshed by the adapter: the client
must fetch and review the changed resource before approving a new operation.

Errors use ApiError `{code,message}` with sanitized stable codes. Snapshot access
is internal: the adapter must authorize and filter project/task/balance queries.
SSE notification IDs are adapter cursors, not provider cursors. Reading/replaying
a notification does not mark it read; only the explicit read mutation does.

The public worker directory exposes `CalendarSummaryView` with checked weekly
commitment totals, never reservation project/milestone IDs. `WorkerView` and its
detailed reservations remain internal provider data.

## Browser integration

The complete public schema is `contracts/openapi.json`. The adapter serves it at
`/api/openapi.json` from `OPENAPI_PATH` (default `contracts/openapi.json`).
Registration, login, the schema document and individual dispute reads are public;
every other route requires a session.

The cookie is `kunveno_session`, HttpOnly, SameSite=Lax, Path=/api, with a 24-hour
lifetime. Secure is enabled outside local HTTP development. Both frontend clients
send `credentials: "include"`. Credentialed cross-origin access requires an exact
allowed Origin. Separate same-site origins work with this cookie policy; unrelated
cross-site hosting requires an explicit cookie/TLS decision, not relaxed defaults.
Authenticated mutations also send `X-CSRF-Token` from the current `SessionView`.
Usernames are 3–64 ASCII letters/digits or `._-`, normalized to lowercase;
passwords are 12–1024 UTF-8 bytes. The browser never receives signing keys.

```javascript
const session = await fetch(`${apiBase}/api/auth/session`, {
  credentials: "include",
}).then(response => response.json());
// Retain this operation ID for every retry of this exact acceptance.
const operationId = `0x${crypto.randomUUID().replaceAll("-", "")}`;
const response = await fetch(`${apiBase}/api/projects/${projectId}/planning/accept`, {
  method: "POST",
  credentials: "include",
  headers: {
    "Content-Type": "application/json",
    "X-CSRF-Token": session.csrfToken,
    "Idempotency-Key": operationId,
  },
  body: JSON.stringify({ expectedRevision: reviewedPlanning.revision }),
});
if (!response.ok) throw await response.json();
const operation = await response.json(); // 202: poll operation.operationId.
```

Do not treat HTTP 202 as completed work. Poll the session-owned operation route;
another user's operation ID returns 404. `OutcomeUnknown` needs reconciliation,
not a fresh business operation. A finalized receipt still needs its execution
outcome checked. Revisions, cursors and timestamps are u64 JSON integers; clients
must preserve exact integers rather than round values above JavaScript's safe
integer range. Money is always an exact decimal string.

SSE uses event name `notification`, `id` equal to `notificationId`, and JSON
`NotificationView` in `data`. Native EventSource uses `withCredentials: true` for
cross-origin requests. `Last-Event-ID` takes precedence over `after`; after defaults
to zero. Both refer to adapter notification cursors, never provider event cursors.
The notification list has a fixed page size of 100. Replayed delivery may repeat
an ID and never marks it read; only POST to the explicit read route does that.

HTTP errors are sanitized `ApiError` objects: invalid request 400, missing/invalid
session 401, permission/CSRF/Origin denial 403, unavailable resource 404, identity
or idempotency conflict 409, oversized request 413, capacity limit 429, unexpected
failure 500, and unavailable dependency 503. Domain failures after enqueue appear
in `OperationView`; they do not change the already returned HTTP 202.
