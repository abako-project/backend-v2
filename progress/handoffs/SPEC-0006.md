Task: verify approved profiles, catalog requests, canonical task-storage routes
and adapter PostgreSQL; port the legacy client/developer profile image attachment

`feat/spec0006-profile-images` in a temporary worktree under `/tmp`, merged
into `master` after verification. No repository-local worktree was created.

## Decisions and scope

- Legacy stores `imageData` and `imageMimeType` on client/developer entities and
  exposes upload/read routes. Rust uses one image per client/worker profile
  section, owned by the adapter. Raw `/api` upload replaces legacy multipart
  `v1` wire format; the two frontends use the documented OpenAPI route.
- The session determines the writer. Public reads expose only image bytes and
  validated MIME. PNG, JPEG and WebP signatures are checked; SVG and arbitrary
  files are excluded. Uploads are limited to 1 MiB on that route only; other
  commands retain the existing 256 KiB body limit. No new dependency was added.
- Migration `0004_profile_images.sql` adds nullable `BYTEA` and MIME columns
  to adapter-owned profile tables. It is additive and runs inside the existing
  advisory-locked startup transaction. Existing rows need no backfill. Roll
  forward on failure; do not drop the columns because that would delete images.
- The nested task routes are write aliases. The accepted direct task read and
  project projection replace an inaccurate Gherkin reference to a nested read.
  Business truth, provider state, escrow and the happy path are unchanged.
