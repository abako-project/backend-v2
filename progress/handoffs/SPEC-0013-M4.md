## Implemented

- Separate exact scores retain hundredths-of-stars times weighted committed
  minutes. Unrated compares as 2.5, with no invented vote. Continued fractions
  avoid overflowing cross-products; additions are checked. Near-limit arithmetic,
  exact ties, invalid stars, overflow and zero weights have canonical unit coverage.
- The validated four-byte score policy matches v1 SCALE. Root-only updates also
  run through the actual signed shell, with matching receipts/nonces/events.
  Future contributions use current weights; old scores never recalculate.
- Internal fixed-controller reputation contributions are idempotent by
  `(project_id, author)` and content hash. A conflicting repeat rejects; partial
  batch errors revert all changes. Actual Project participants/required targets,
  completion checks and retained evaluations remain M6, not a public shortcut.
- The skill index uses individually stored dense entries/positions/counts.
  Qualifications update membership without scanning every worker. Matching
  intersects all skills, filters mode/capacity, excludes client/coordinator and
  already-used slots, prefers eligible earlier-milestone team members, then uses
  exact relevant scores and uniform ties. Role metadata never filters candidates.
  Candidate sorting and the one captured RNG stream reproduce native behavior.
- Initial coordinator selection uses eligibility/mode/current weekly capacity
  and excludes the client. It returns the following ID from the same entropy
  stream, preserving native selection-before-ID order for the M5 factory.
- All milestone selections/reservations share one transaction and RNG. Any error
  reverts earlier reservations, including earlier milestones. Existing reservations
  remain append-only. No new release/refund rule is introduced.
