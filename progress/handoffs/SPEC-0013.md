## Delivered scope

The isolated `tools/ink-sandbox` workspace executes canonical v5 production WASM
using a coherent pallet-contracts 43 / FRAME 43 dependency family. It pins the
three existing contracts plus a failure probe, source commit, toolchains,
artifact hashes and build locks. The minimal asset extension matches Kreivo's three local-asset functions
and rejects unsupported functions. The proof covers cross-calls, direct caller
funding, `Preserve`, settlement, rejected mutations, nested rollback, gas
exhaustion of an endless storage-writing loop, explicit traps and raw-trie restart including contract Mapping data.

The provider now separates `RustEngine` business state from the envelope shell.
Only the shell owns signature validation, nonces, receipts and the event log.
The engine receives root/cursor context and operation-local randomness. Accepted
operations retain a versioned entropy seed and timestamp with their receipt for
reproduction. IDs and unbiased tie choices use the same captured input stream;
there is no business call to OS/thread-local randomness. Replay returns before
capturing new input. Failed business state is discarded while its receipt/nonce
still commit; infrastructure failures commit nothing.

The application dependency graph and public contracts are unchanged. SQLite
keeps its version-1 row and flat JSON representation. An explicit typed decoder
reads old catalog integer keys, exact amounts and old records without entropy
inputs. New engine-version and recorded-input fields are additive; unknown
engine versions reject startup. No data reset, release, tag or deployment is
part of this work.

Version-1 input reproduction is tied to the current locked rand 0.10.2 native
build. A changed generator/target must introduce a new input version rather than
reinterpret existing seeds. This is reproducibility support, not secure onchain
randomness or a substitute for explicit candidate ABI inputs.

## Remaining gates

This is a compatibility proof and engine-boundary release, not the completed
canonical-contract migration. No sandbox/shadow authority mode is exposed.
Existing contracts still implement their legacy product rules. Milestones 2–8
remain: bounded worker and verified provider checkpoints, updated canonical
contract domains, full parity, preserving import, rollback and authority switch.

Provider integration is blocked on disposition of the SDK dependency-policy
findings in [the dependency review](../../tools/ink-sandbox/dependencies.md).
No policy exception has been assumed. Continue independently with the working
Rust engine and do not promote the candidate until this gate is resolved.

The money port must preserve full user balances/payouts despite Kreivo's asset
minimum. Use the approved separate technical reserves; the legacy fixture's
one-unit payout reduction must not become application behavior. Production
checkpoint validation must include bundle/runtime identity, bounded decode,
root validation and SQLite atomic commits; the proof format is not that format.

Performance acceptance is still pending. The current fixed fixture is three
contracts, one calendar member and one legacy task/budget of 100 units, with a
failed approval and a failed final payout. Its test duration is not an engine
p95 measurement and cannot prove four-milestone approval or startup budgets.
A representative current-app workload is required when candidate domains exist.
