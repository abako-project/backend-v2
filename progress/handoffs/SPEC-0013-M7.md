## Implementation

A shared typed ArchiveV1 includes all domain and shell state: private skill
metadata, ordered reasons, scores as exact u128, all Bramp records, task IDs and
counters, balances/issuance, nonces, unsigned bytes, captured inputs, receipts,
events and generation. Export runs off Tokio. Fresh native memory/SQLite imports
validate the archive, reject any populated or unsupported-format destination
without changing it, and atomically mark imported SQLite stores against reseeding.
Native foundation b30e60f was independently reviewed and passed the app gate.

Directory creates dormant children, copies retained facts without replaying
payments, notifications or reputation, and permanently seals only after complete
comparison. Imported evaluation markers prevent a second historical contribution.
Legacy acceptance preserves coordinator-overflow priority before worker lookup.
Each migration record and Calendar/Project image uses ordered 8 KiB pages; registry
records use a separate temporary namespace. A root-owned capability permits
record pages only during import. The final page atomically applies and clears the
record, leaving an idle capability until sealing removes it forever. Failed pages
or decoding restore the prior checkpoint. Incomplete records block sealing.

Worker skill indexes rebuild in fixed batches of at most 32 entries, preserving
the ordinary 16 MiB proof budget. Skill zero is invalid; its existing position
cell tracks migration batch progress. Seal requires every worker's index complete.
The SDK explicitly validates the finished/idle header for each import phase.
Native archives must first pass native admission and callers must pause/drain
writes and reconcile ambiguous outcomes before import.

The storage helper streams bounded pages below Kreivo's unchanged 16 KiB cell
limit. Exact-allocation Text adapters retain public String types and SCALE bytes.
Directory normalization collapses whitespace before the same Unicode17 lowercase
operation, without a temporary vector/join. Existing M6 messages and selectors
remain. Canonical b2a7cfa builds Directory at196593 bytes, below196608; this leaves
little code headroom and future changes must recheck it. Calendar/Project pins
are unchanged from the reproduced bbc1873 cohort. The immutable storage helper
pins are f147e59 (Calendar),54643f5 (Directory),09ca7be (Project).

SDK import commits runtime and complete retained shell together into a fresh
store. Reopen rejects missing/incompatible state. Read-only storage export checks
all pinned layouts, parent/id/liveness, global/local reason order, dispute ownership
and exact balances with cumulative64MiB cell/archive limits. Runtime checkpoints
and shell each have64MiB caps. A successful whole-candidate write must remain
completely exportable before commit. Queries discard effects. Comparison checks
complete archives, exact receipts and error classes; missing coverage/export is
Incomplete, never agreement. There is no fallback or automatic re-execution.
